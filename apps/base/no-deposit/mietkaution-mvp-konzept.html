01 · Kontext

Business-Logik & Akteure

Die Plattform ermöglicht es Mietern, ihre Mietkaution digital zu hinterlegen, ohne den Betrag selbst aufbringen zu müssen. Die Agentur agiert als Intermediär zwischen Mieter und Vermieter und übernimmt die Bürgschaft gegen eine Gebühr.

Mieter

  • Registrierung & KYC
  • Kautionsantrag stellen
  • Bürgschaftsurkunde abrufen
  • Zahlungen verwalten
  • Status-Tracking

Vermieter

  • Bürgschaft validieren
  • Schadensfall melden
  • Dokumente empfangen
  • Mietverhältnis verwalten

Agentur (Admin)

  • Anträge prüfen & freigeben
  • Risikobewertung
  • Schadensfall bearbeiten
  • Reporting & Compliance

System

  • Automatische Benachrichtigungen
  • Zahlungsabwicklung
  • Dokumentengenerierung
  • Audit-Logging
02 · Architektur

Systemarchitektur

Zwei-Tier-Deployment: Keycloak auf AWS (dauerhaft, stateful), Django-Applikation auf Heroku (skalierbar, dyno-basiert). RDS PostgreSQL als gemeinsame Datenbasis.

CLIENT Browser Mobile PWA → Heroku CDN / Edge
↓ HTTPS
HEROKU Django App (Web Dynos) ←→ Celery Worker (Dynos) ←→ Redis (Heroku Add-on)
↓ OAuth2/OIDC Token Validation        ↓ SQL
AWS Keycloak (EC2 / ECS) ←→ RDS PostgreSQL ←→ S3 (Dokumente)
↓
EXTERN SES (E-Mail) SNS (Notifications) Stripe / SEPA SCHUFA API
Deployment-Entscheidung: Hybrid Keycloak benötigt persistenten State (eigene PostgreSQL-DB, Session-Store) → AWS EC2 oder ECS ist stabiler als ein Heroku Dyno. Django-App hingegen ist zustandslos und profitiert von Heroku's simplem Deployment-Workflow (git push, Review Apps, Pipelines).

04 · Auth

Keycloak & Authentication Flow

Realm-Konfiguration

# Keycloak Realm: mietkaution-prod
realm: mietkaution-prod
clients:
  - client_id: django-app
    protocol: openid-connect
    access_type: confidential
    redirect_uris:
      - https://app.mietkaution.de/oidc/callback/
    scopes: [openid, profile, email, roles]

roles:
  - mieter        # Kautionsanträge, eigene Daten
  - vermieter     # Bürgschaft validieren, Schäden melden
  - agent         # Anträge bearbeiten, freigeben
  - admin         # Full access, Konfiguration

identity_providers:
  - google         # Social Login (optional)
  - bankid         # Starke Identifikation (Phase 2)

mfa_policy:
  - agent: required
  - admin: required
  - mieter: optional

Django OIDC Integration

# settings.py (Auszug)
AUTHENTICATION_BACKENDS = [
    'mozilla_django_oidc.auth.OIDCAuthenticationBackend',
]

OIDC_RP_CLIENT_ID     = env('KEYCLOAK_CLIENT_ID')
OIDC_RP_CLIENT_SECRET = env('KEYCLOAK_CLIENT_SECRET')
OIDC_OP_AUTHORIZATION_ENDPOINT = (
    'https://auth.mietkaution.de/realms/mietkaution-prod'
    '/protocol/openid-connect/auth'
)
OIDC_RP_SIGN_ALGO     = 'RS256'
OIDC_VERIFY_SSL       = True

# Rollen aus JWT-Token mappen
class KautionOIDCBackend(OIDCAuthenticationBackend):
    def update_user(self, user, claims):
        roles = claims.get('realm_access', {}).get('roles', [])
        user.is_staff = 'agent' in roles or 'admin' in roles
        user.save()
        return user
05 · API

RESTful API Design

Alle Endpunkte sind JWT-gesichert (Bearer Token aus Keycloak). Rollenbasierte Zugriffskontrolle per DRF Permission Classes.

Kautionsanträge

POST /api/v1/applications/ Neuen Kautionsantrag einreichen (Mieter)
GET /api/v1/applications/{id}/ Antragsstatus abrufen
PATCH /api/v1/applications/{id}/review/ Antrag prüfen/genehmigen (Agent)
POST /api/v1/applications/{id}/documents/ KYC-Dokumente hochladen (→ S3)

Bürgschaften

GET /api/v1/guarantees/{id}/ Bürgschaftsdaten abrufen
GET /api/v1/guarantees/{id}/certificate/ PDF-Urkunde generieren & herunterladen
POST /api/v1/guarantees/{id}/validate/ Bürgschaft validieren (Vermieter via Token)

Schadensfall

POST /api/v1/claims/ Schadensfall einleiten (Vermieter)
PATCH /api/v1/claims/{id}/decision/ Entscheidung treffen (Agent)

Zahlungen

POST /api/v1/payments/intent/ Stripe Payment Intent erstellen
POST /api/v1/webhooks/stripe/ Stripe Webhook (Zahlungsbestätigung)
06 · Datenmodell

Kernmodelle (Django ORM)

# models.py (vereinfacht)

class UserProfile(models.Model):
    user        = models.OneToOneField(User, ...)
    keycloak_id = models.UUIDField(unique=True)   # Keycloak sub claim
    role        = models.CharField(choices=ROLES)  # mieter/vermieter/agent
    kyc_status  = models.CharField(choices=KYC_STATUS)
    schufa_score = models.IntegerField(null=True)

class RentalApplication(models.Model):
    applicant   = models.ForeignKey(UserProfile, ...)
    landlord    = models.ForeignKey(UserProfile, ...)
    address     = models.TextField()
    rent_amount = models.DecimalField(max_digits=10, decimal_places=2)
    deposit_amt = models.DecimalField(...)         # i.d.R. 3x Nettomiete
    status      = models.CharField(choices=STATUS) # pending/approved/rejected
    created_at  = models.DateTimeField(auto_now_add=True)

class Guarantee(models.Model):
    application    = models.OneToOneField(RentalApplication, ...)
    certificate_no = models.CharField(unique=True)
    valid_from     = models.DateField()
    valid_until    = models.DateField()
    s3_key         = models.CharField()            # PDF in S3
    validate_token = models.UUIDField(default=uuid4) # Vermieter-Link

class Claim(models.Model):
    guarantee   = models.ForeignKey(Guarantee, ...)
    claimant    = models.ForeignKey(UserProfile, ...)
    amount      = models.DecimalField(...)
    description = models.TextField()
    status      = models.CharField(choices=CLAIM_STATUS)
    documents   = models.ManyToManyField('Document')
07 · CI/CD

Deployment Pipeline

# .github/workflows/deploy.yml
name: CI/CD Pipeline
on:
  push: { branches: [main, staging] }
  pull_request: { branches: [main] }

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Django Tests + Coverage
        run: |
          pytest --cov=. --cov-fail-under=80
          bandit -r . -x tests/          # Security scan

  deploy-staging:
    needs: test
    if: github.ref == 'refs/heads/staging'
    steps:
      - name: Deploy to Heroku Staging
        uses: akhileshns/heroku-deploy@v3
        with: { heroku_app_name: mietkaution-staging }

  deploy-prod:
    needs: test
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Deploy to Heroku Production
        run: |
          heroku run python manage.py migrate
          # Zero-downtime via Heroku Preboot

09 · Security

Security-by-Design

🔐
Auth

Zero-Trust Token Validation

Jeder API-Request validiert JWT gegen Keycloak JWKS. Kein Session-Cookie, kein serverseitiger State.

🛡️
DSGVO

Datensparsamkeit

KYC-Dokumente nur in S3 mit Pre-Signed URLs. Kein PII in Logs. Verschlüsselung at-rest (RDS, S3).

🔒
Secrets

AWS Secrets Manager

Alle Credentials (DB, Stripe, Keycloak) über AWS Secrets Manager. Kein Hardcoding, Rotation automatisiert.

📋
Audit

Vollständiges Audit-Log

Jede Statusänderung an Anträgen, Bürgschaften, Claims mit User-ID, Timestamp, IP in unveränderlicher Tabelle.

🧱
Network

VPC Isolation

RDS und Keycloak in privaten Subnets. Nur Django-App hat Zugriff. Security Groups strikt nach Least Privilege.

⚡
API

Rate Limiting & Throttling

DRF Throttling pro User/IP. Login-Endpoints mit Brute-Force-Schutz via Keycloak Policy.
